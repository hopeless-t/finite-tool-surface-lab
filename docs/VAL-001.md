# VAL-001 — Synthetic Registry / Harness Validation

## Question

Can the lab generate controlled Tool registries and gold task labels reproducibly, and can the harness detect broken controls before any model-in-the-loop experiment?

## Purpose

This validates the research apparatus. It does not test the hypothesis that smaller surfaces improve Workers.

## Frozen factors

Registry size:

```text
8, 32, 128, 512, 2048
```

Task classes:
- single-tool;
- multi-tool;
- no-tool.

Controlled factors:
- semantic overlap;
- alias rate;
- distractor density.

## Required controls

ORACLE: surface equals gold relevant set.  
FULL: surface equals complete registry.  
RANDOM-k: chance baseline with analytically checkable expected coverage.

## Acceptance

VAL-001 PASS requires:

- same generator version + seed produces byte-identical fixtures;
- all required gold IDs exist in the registry;
- no-tool tasks have empty gold;
- ORACLE equals gold exactly;
- FULL equals registry exactly;
- invalid specs fail before calculation;
- intentional broken-control fixture is detected;
- empirical RANDOM-k coverage agrees with finite-population expectation within frozen tolerance.

PASS validates the harness/generator only.

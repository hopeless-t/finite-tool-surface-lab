# VAL-002 — External Tool Catalogue Adapter / pmndrs-math

## Question

Can a pinned external package be converted into a deterministic Tool catalogue with explicit equivalence and hard-negative structure?

## Source

`math@0.1.0` from `pmndrs/math`.

The package is already dogfooded separately. VAL-002 does not reclassify it as an adopted lab dependency.

## Corpus semantics

Runtime-exported functions are represented as Tool records:

```text
namespace
operation name
arity
API description
function-identity equivalence group
cross-namespace homonym group
```

### Valid equivalent

Within one namespace, aliases that are the same JavaScript function object are valid equivalents.

Example:

```text
vec3.distance
vec3.dist
```

### Cross-type homonym

The same operation name in different typed namespaces is not automatically equivalent.

Example:

```text
vec2.distance
vec3.distance
vec4.distance
```

For a query that explicitly asks for 3D vectors, vec2/vec4 are plausible hard negatives.

```text
Lexical Similarity
!= Semantic Equivalence
```

## Dogfood calculation

The adapter uses `mulberry32` from `math/random` for deterministic sampling of alias and homonym pairs.

This is deliberate Tool dogfooding.

The adapter could use Python's RNG, but using the candidate Tool here gives direct evidence that its deterministic calculation primitive composes cleanly into the research workflow.

## Reproduction

The GitHub workflow runs the extractor under Node 20 and Node 22.

Stable `catalog.json` must be byte-identical.

Runtime metadata is recorded separately and is not used to manufacture equivalence labels.

## Claim ceiling

VAL-002 qualifies the adapter/corpus identity only.

It does not measure retrieval performance and does not qualify the package for MVCA execution.
